Tu travailles sur le projet ForgeKit.

Repository upstream :
https://github.com/Demetrius-ch/forgekit

ForgeKit est un outil CLI Go destiné à créer et maintenir des APIs REST Go avec une architecture hexagonale.

============================================================
PHASE
============================================================

Phase Debian Official — ITP + Sponsor + Upload

OBJECTIF FINAL

Préparer ForgeKit pour une première intégration officielle dans Debian.

Le résultat attendu est un paquet Debian SOURCE correctement préparé, conforme aux Debian Policy et aux pratiques Debian, prêt à être soumis à Debian Mentors puis à un sponsor Debian pour review et upload.

IMPORTANT :

Nous ne cherchons PAS simplement à publier le .deb généré par GoReleaser.

Le paquet officiel Debian doit être construit depuis les sources ForgeKit dans un environnement Debian propre et reproductible.

Le workflow cible est :

ForgeKit upstream
    ↓
Debian packaging
    ↓
ITP
    ↓
Debian Mentors
    ↓
RFS / recherche d'un sponsor
    ↓
Review du sponsor
    ↓
Corrections éventuelles
    ↓   
Upload par le sponsor
    ↓
Debian NEW / FTP Masters
    ↓
Debian unstable
    ↓
éventuelle synchronisation Ubuntu
    ↓
Ubuntu App Center / dépôt Ubuntu

============================================================
RÈGLES ABSOLUES
============================================================

1. NE PAS publier une nouvelle release upstream.
2. NE PAS créer de nouveau tag Git.
3. NE PAS pousser de modifications sur GitHub sans validation explicite.
4. NE PAS uploader quoi que ce soit vers Debian Mentors sans validation finale explicite.
5. NE PAS contacter un sponsor automatiquement.
6. NE PAS modifier l'architecture fonctionnelle de ForgeKit.
7. NE PAS remplacer le système de build upstream par une solution arbitraire.
8. NE PAS utiliser un binaire précompilé dans le paquet Debian officiel.
9. NE PAS télécharger des dépendances Go depuis Internet pendant le build Debian.
10. Le paquet doit être construit depuis les sources.
11. Le build doit être reproductible autant que raisonnablement possible.
12. Toute modification Debian doit rester confinée au packaging Debian sauf nécessité justifiée.
13. Ne jamais considérer le .deb GoReleaser comme preuve suffisante de conformité Debian.
14. Ne jamais supprimer une fonctionnalité existante de ForgeKit pour simplifier le packaging.
15. Avant toute modification importante, inspecter l'état actuel du repository.

ÉTAPE 2 — VÉRIFIER LE NOM DU PAQUET
============================================================

Le nom Debian souhaité est :

forgekit

Le binaire principal doit être :

/usr/bin/forgekit

Vérifier attentivement si le nom "forgekit" existe déjà dans Debian.

Vérifier également le statut du nom "forge" et les éventuels conflits de fichiers/binaires Debian.

IMPORTANT :

Le projet a historiquement utilisé le binaire "forge".

Nous voulons conserver la compatibilité "forge" lorsque cela est techniquement et juridiquement acceptable.

Mais NE PAS imposer aveuglément :

/usr/bin/forge -> /usr/bin/forgekit

dans le paquet Debian officiel.

Avant de conserver cette compatibilité, vérifier :

- collision potentielle avec un paquet Debian existant
- Debian Policy
- ownership du fichier
- Replaces
- Provides
- conflits éventuels
- intérêt réel de conserver cet alias

Si l'alias pose un problème Debian, documenter le problème et proposer la solution la plus propre.
